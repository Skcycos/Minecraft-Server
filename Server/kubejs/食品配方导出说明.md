# 食品配方 CSV 导出

服务端启动完成后，以控制台或管理员身份执行：

```mcfunction
/syexport food_recipes
```

KubeJS 的脚本沙箱只能安全写入 JSON，先生成 `kubejs/config/food_recipe_export.json`；随后在仓库根目录执行：

```sh
node Server/tools/export_food_recipe_csv.mjs
```

即可生成 CSV 到 `Server/kubejs/config/food_recipe_export/`。转换脚本会加入 UTF-8 BOM，Excel 可直接识别中文。

| 文件 | 用途 |
| --- | --- |
| `food_recipes.csv` | 一条配方一行的食品配方总表，适合菜单、Wiki 和人工核对。 |
| `food_recipe_ingredients.csv` | 一种原料一行；原料有多个可选物品时用 `/` 分隔。适合 Excel 筛选和成本统计。 |
| `food_recipe_outputs.csv` | 一种固定产物一行，包含数量、饥饿值、饱食度和食用效果。 |
| `food_recipe_mod_summary.csv` | 各来源模组的导出数量，用于核对筛选范围。 |

默认纳入的来源模组为：`farmersdelight`、`kaleidoscope_cookery`、`ordertocook`、`kaleidoscope_compat`、`spawn`（动物生态中的鱼类、蒸蛤蜊、罐装鲱鱼等食品）。

## 字段说明

- `配方中文译名（主产物）`：Minecraft 没有为配方 ID 提供统一的翻译字段，故默认使用主产物中文名作为配方译名；原始 `配方 ID` 始终保留用于精确定位。
- `合成机器/工序`：常见配方类型会翻译为工作台、切菜板、烹饪锅、万花筒汤锅、炉子等；未知类型保留原始序列化 ID。
- `经验值`、`烹饪时间(tick)`：仅适用于原版烹饪类配方；其他类型为空不代表没有自定义参数。
- `饥饿值`、`饱食度`、`食用效果/BUFF`：读取成品的食品组件，而非只读取配方 JSON。
- 原料会由转换工具直接读取模组 JAR 中的原始配方 JSON，因此万花筒烹饪等自定义机器的原料、容器/载体和工具也会写入总表及原料明细表。
- 流体、容器返还、概率产物、温度等尚未标准化为独立列；需要时仍应以 JEI 和配方源 JSON 为准。

中文名读取服务端已加载物品名称；若某个模组仅在客户端提供中文语言文件，则保留服务端默认名称。

## 扩展范围

若希望连同机械动力等其他模组“产出食物”的工序也导出，请在
`server_scripts/export_food_recipes.js` 中将 `includeFoodOutputsFromOtherMods` 改为 `true`，随后执行 `/reload` 再导出。
